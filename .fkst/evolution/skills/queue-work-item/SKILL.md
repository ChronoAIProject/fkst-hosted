# Queue a work item onto a running session

> **Generated artifact** (`skill.queue-work-item`). Regenerated by FKST Evolution
> from capability `cap_9d41`. Do not hand-edit; change the product model instead.

## Purpose and bounded scope

Add exactly one work item to one already-running session.

**In scope:** opening the work issue, choosing the correct label, and confirming
the session claimed it.

**Out of scope:** creating a session (that is a trigger issue), retiring one
(close the trigger), and anything that requires changing a session's frozen
configuration — a registered trigger's configuration is immutable, and editing it
is ignored and flagged.

## Prerequisites and required permissions

You MUST hold work authority on the target session. Work authority is exactly
one of:

- you are the session's **effective creator** (the trigger issue's author, or its
  sole assignee when the trigger was App-authored);
- your login is frozen under the session's **`### Session Collaborators`**; or
- you are a **deployment global administrator**.

Repository `admin` or `maintain` permission is **not** work authority. This trips
people constantly: you can be able to administer the repository and still be
refused.

You also need a GitHub token that can open issues on the repository — the issue
is created *as you*.

## Inputs

| Input | Required | Notes |
| --- | --- | --- |
| `owner` / `name` | yes | The repository |
| `issue_number` | yes | The **session's trigger-issue number**, not the work issue |
| `title` | yes | Rejected when blank after trimming |
| `body` | no | Markdown. Original whitespace is preserved; omit for a body-less issue |
| selected work label | yes | MUST be one of the session's applicable work labels |

Resolve the applicable label set from the session before choosing one. Do not
guess a label string — a label that is not applicable is refused, and a *valid*
label belonging to a different session routes the work to that session instead.

## Operation

`POST /api/v1/repos/{owner}/{name}/sessions/{issue_number}/work-items`

Expected output on success — HTTP **201**:

```json
{
  "issue_number": 999,
  "html_url": "https://github.com/<owner>/<name>/issues/999"
}
```

The equivalent manual path is to open an issue on the repository carrying that
same work label and assigned to the session's effective creator. The dashboard
composer is a convenience over that protocol, not a separate control plane, so
both produce the same result.

## Side effects

- A new **public-to-the-repository GitHub issue** is created, authored by you.
- The session's reconciler claims it and the session begins working it.
- The session's pod is kept alive while that issue stays open. An open work-label
  issue prevents the session from idling down; a created-but-unmerged pull
  request does not.

## Deterministic success verification

1. The response is `201` and carries an `issue_number` and `html_url`.
2. Fetching that issue shows the selected work label and exactly one assignee —
   the session's effective creator.
3. Within the reconcile sweep the issue receives the durable `fkst-picked-up`
   acknowledgement.

Do not treat a `201` alone as "the session is working it". Step 3 is the claim.

## Known failure modes

| Symptom | Cause | Remedy |
| --- | --- | --- |
| `400` | Blank title, malformed owner/name/issue number, or GitHub rejected the issue | Send a non-empty trimmed title |
| `401` | Missing or invalid GitHub token | Re-authenticate |
| `403` | No work authority, not allowlisted, or GitHub refused the write for you | Get added to `### Session Collaborators`, or have the session's creator queue it |
| `404` | No such trigger issue, or you cannot see the repository | Check the trigger number and your repository access |
| `409` | The session trigger is closed | The session is retired; start a replacement and assign work to its creator |
| `422` | Trigger or package sources malformed, no applicable work labels, or the selected label is not applicable | Re-read the session's effective label set |
| `503` | GitHub API unreachable | Retry; the operation is not lost, it simply did not happen |
| Issue commented `fkst-unrouted` | Zero/multiple assignees, or the sole assignee is not a matching active session's creator | Fix the assignee; the latch self-heals |
| Issue labelled `fkst-unauthorized` | The issue's *author* lacks work authority | It stays unworked until the author becomes authorized |
