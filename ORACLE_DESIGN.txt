I read the code path. The best fix is not “make every consumer lenient” as the primary policy. The best fix is:
Define one PR-review consensus dedup constructor/parser pair, canonicalize the review-result boundary at write time, and keep read-side canonicalization only for legacy markers already written with /loop/N.
The /loop/N suffix is meaningful for the consensus run and review convergence telemetry. It is not meaningful for the review-result outcome marker. The initial PR review proposal dedup is <review_id>/review, and review-loop proposals add transition_version.loop_at(...), which creates <review_id>/review/loop/N; consensus then wraps the proposal dedup as consensus:<proposal.dedup_key>.
The bug is exactly that this consensus-run identity leaks into the outcome marker and downstream handoffs. review_result/main.lua starts with the raw reached payload as comment_reached; requests/review.lua writes reached.dedup_key into the review-result:v1 marker, merge-ready marker, reflection marker, comment dedup, and handoff payloads; then facts.lua insists the marker dedup exactly equals consensus:<review_proposal>/review, so /loop/N makes the reject fact disappear.    The fix worker then calls review_reject_fact; if it is nil, it retries with fix-feedback-marker-missing and never reaches the Codex attempt.
Why canonicalizing at write is correct
A review-result:v1 marker is not “the result of convergence loop 3.” It is “the accepted PR review outcome for this review proposal, reviewed head, issue version, and fix round.” The review proposal ID already carries PR number, version segment, and head SHA.  Reject markers also carry fix_round separately and validate that it matches the issue version’s fix round.  So stripping /loop/N from the outcome marker does not collapse distinct fix rounds. It collapses duplicate convergence attempts for the same reviewed head into one outcome, which is exactly the idempotency shape the rest of the code already expects.
The only thing we lose by stripping is provenance of which convergence round yielded the final consensus. That provenance belongs on review-converge markers or an explicit provenance attr, not in the review-result identity.

Other parser sites and class status
This is a class bug, not a one-off. The class is “review consensus dedup is reconstructed or parsed ad hoc.” Current examples:


facts.lua constructs and compares the base form directly, and its parser is anchored to /review$.


pr_review_replay_facts.lua uses a different, unanchored parser. It happens to tolerate /loop/N, but it is still a second grammar.


hidden_state_conformance.lua and review_carry_over.lua construct the base string manually.


The helper pair kills the class by making the framework own both shapes:


pr_review_proposal_dedup_key(review_proposal_id) creates the consensus proposal dedup without consensus:.


pr_review_consensus_dedup_key(review_proposal_id) creates the marker/event binding form with consensus:.


canonical_pr_review_consensus_dedup_key(dedup) strips only a trailing /loop/N.


canonical_pr_review_consensus_dedup_for_proposal(dedup, proposal_id) verifies the dedup and proposal match.


That still lets review-converge and review-meta markers keep /loop/N where it is genuinely part of their event identity. It prevents the review-result outcome marker, merge-ready marker, fixing handoff, high-risk evidence marker, and carry-over checks from drifting.
Decompose escalation
There are two separate paths.
Max fix rounds: the existing path appears intentionally wired to decompose. When review-result receives a reject and fix_round >= max_fix_rounds, it raises both devloop_fix_reconcile and github-devloop-decompose.devloop_decompose.  The decompose department consumes devloop_decompose, but waits until the blocked/fix-reconcile marker is visible before creating child issues.   So for “fix genuinely cannot converge after max_fix_rounds,” the intended decompose path is present.
Fixing timeout: this is a separate defect if the intended product behavior is “too big should split, not timeout to blocked.” The generic liveness timeout helper force-terminates to blocked after retries.  The timeout reconcile pipeline writes a blocked timeout-reconcile result for non-blocked states and does not raise devloop_decompose; it only emits a decompose-exhausted marker when the state is already blocked and the decompose output obligation itself has timed out.   That should not be mixed into #1999. It needs a second patch: the fixing timeout reconciliation policy should raise a fix-reconcile plus decompose, or transition through the same max-fix-round decompose pathway, rather than directly blocking.
===CONCLUSION===
(a) Pick: unify constructor/parser plus canonicalize at write. Read-side tolerance is included only to heal already-written /loop/N review-result markers and already-queued loop-suffixed fixing payloads.
(b) Exact files: libraries/devloop/base.lua, libraries/devloop/payloads/builders.lua, packages/github-devloop-pr/departments/review_result/main.lua, libraries/devloop/requests/review.lua, libraries/devloop/markers/facts.lua, packages/github-devloop-pr/departments/fix/main.lua, libraries/devloop/restart/pr_review_replay_facts.lua, libraries/devloop/hidden_state_conformance.lua, packages/github-devloop-pr/core/review_carry_over.lua, plus regression tests in packages/github-devloop-pr/tests/integration_pr_review_result_test.lua and a low-level facts parser test.
(c) #1999 is a class bug. The class is scattered PR-review consensus dedup grammars. The fix kills it by centralizing construction and parsing, then making review-result writers emit only one canonical identity.
(d) Decompose escalation is a separate needed fix for fixing timeout, not for max_fix_rounds. Max fix rounds already raises fix-reconcile plus decompose. Timeout reconcile still blocks directly and does not raise decompose.
(e) Biggest risk: over-normalizing dedups that are truly per-converge-round, especially review-meta and review-converge markers. The mitigation is to canonicalize only review-result outcome bindings and to leave review-meta/converge marker identity raw where /loop/N is load-bearing.
